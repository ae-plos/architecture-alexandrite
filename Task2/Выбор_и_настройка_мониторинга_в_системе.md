# Мотивация

1. Поскольку компания развивает рынок сбыта для b2b по средством предоставления API, мониторинг требуется для того, что бы сторонние интеграционные 
   команды в случае ошибок со своей стороны (перегрузка, дублирование, ошибочные запросы) не вывели из строя нашу систему
2. С использованием метрик можно получать не только технические показатели производительности системы, но и бизнесовые. Например, конверсия клиентов,
   сроки жизни заказа, сроки обслуживания клиента (разделенные по отделам - сейл, оператор, изготовитель). Причем, это может быть дешевле чем 
   построение DWH или простых аналитических БД
3. Метрики позволят команде выявить проблемные места системы, зависание запросов в техническом смысле.

# Выбор подхода к мониторингу

1. RED на БДшки
2. USE для очередей
3. Сервисы LETS (четыре зол. сигн.), а лучше даже STELA - просто мне так привычнее
4. API Gateway Traffic + Latency

Number of requests (RPS) for MES API - просто понимать общий поток в системы
Number of requests (RPS) per user for internet shop API - Лимиты на использование API
Насыщенность сервисов - для понимания нужно ли скалироваться
CPU % for shop API
CPU % for CRM API
CPU % for MES API
Пямять нужна для понимания нормально ли у нас все с индексами и конфигами бд (page cost - тут люди часто ошибаются) + нужно либо схлопнуть инстансы 
если нет высокого TPS, либо мб на монгу (см предыдущее задание)
Memory Utilisation for shop db instance
Memory Utilisation for MES db instance
Время ответ нужно, что бы понять где у нас что затыкается для пользователя (или оркестратора если мы его используем через API а так надо)
Response time (latency) for shop API
Response time (latency) for CRM API
Response time (latency) for MES API
Нужно ошибки в количестве хранить, что бы процент посчитать (1 метрики в списке) или фактическое значение 
Number of HTTP 500 for CRM API
Number of HTTP 500 for MES API
Number of HTTP 500 for shop API
Нужна доступность, что бы быстро получать информацию в какие моменты наш сервис помирает от нагрузки
Availability for CRM API
Availability for MES API
Availability for shop API

Комментарий, это прям необходимый минимум, к тому же который еще быстро внедряется, без которого смысла нет что-то делать дальше в метриках. Дальше, 
нужно допривести метрики в "Выбор подхода к мониторингу", как говорится, по книжке. 
Так же на этапе мотивации проговорить с бизнесом и внедрить специальные для него - в первую очередь его будет интересновать сроки работы менеджеров,
конверсия и может быть еще что-то. В идеальном мире использовать стратегию, а "что вам надо? хорошо, тогда мы получим еще тезхнические метрики по дороге"
