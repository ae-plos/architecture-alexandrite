# Диагранна системы с кэшем

Приложена в файле jewerly_c4_cache.drawio

# Мотивация

1. Кэширование позволит операторам, оперативнее получать информацию о новых заказах
2. Кэширование на UI снизит нагрузку на бекенд и на сервера (статики)
3. Кэширование в сервисе снизит нагрузку на БД и повысит быстродействие

# Предлагаемое решение

1. На стороне UI нужно кэшировать и очень на долго все js, которые относятся к редактору 3D - что бы они часто статикой с сервера не запрашивалсись
2. На стороне UI нужно кэшировать на 5-10 секунд данные по заказу их - тк информация не критичная к обновлению в момент
3. На бекенде MES API нужно в идеале SoftReference кэширование (не редис) для словарей и всякой справочной информации для расчетов
4. Проработать КЭШ write behind для заказов, что бы информация о новых была максильно быстро получаема на скроллерах (указано в проблемах)
